# Zed Z1 (Linux): Default Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Zed the default GUI editor on Linux (Fedora, Ubuntu, Arch/Omarchy). dev-boost installs it, seeds a curated VS Code-style `settings.json`/`keymap.json`, re-applies a small set of required keys on every run with a comment-tolerant (JSONC) deep merge, points Zed at dev-boost's pinned language servers, sets `VISUAL="zed --wait"` in local GUI sessions, and moves VS Code to the opt-in profile.

**Architecture:** There is one new typed module, `zed` (`modules/editors.py`). Its install/verify go through a new, OS-independent helper module, `modules/_zed.py`, which handles seeding, the required keys and LSP binary paths. That helper sits on a new, generic `config.jsonc_merge_deep` primitive. The seed files live in the chezmoi source (`create_` = write once). The module reads the same files through `resource_path`, so the seed has one source. LSP binary paths come from the existing `data/fresh/*.tsv` pins through a small `data/zed/lsp-binaries.tsv` map. The environment block goes in a new POSIX `~/.config/devboost/env.sh`, which `shell.bash` sources. macOS M2 will grow that same file. Z2 (macOS) reuses `_zed.py`, the seed files and `env.sh` unchanged. It only adds `"macos"` to `Zed.families` and a cask branch in `zed_install_argv`.

**Tech Stack:** Python ≥ 3.12, Typer, Pydantic, stdlib `json`/`os`/`pathlib`, pytest, mypy `--strict`, ruff; `uv` for the dev environment. POSIX `sh` for `env.sh`. chezmoi `create_` source attribute.

**Spec:** `docs/superpowers/specs/2026-09-18-zed-default-editor-design.md` (all sections; Rollout row **Z1**). Read it before starting. The macOS parts (cask, `duti`, row Z2) are out of scope.

## Global Constraints

- Linux install: the official `curl -f https://zed.dev/install.sh | sh` (user-local: `~/.local/zed.app`, symlink `~/.local/bin/zed`, no sudo). Run as argv `["sh", "-c", "curl -fsSL https://zed.dev/install.sh | sh"]`.
- Profiles: `editors` = `zed`, `fresh`, `fresh-lsp`; `vscode` moves to `optional-editors`.
- Config files: `~/.config/zed/settings.json` and `~/.config/zed/keymap.json`. Seeded from `dotfiles/dot_config/zed/create_settings.json` / `create_keymap.json`.
- Ownership: **seed once**; after that the user owns the file. Only these keys are re-applied on every run, never removed: `auto_install_extensions` (dev-boost ids; user additions kept), `agent_servers` (the three entries), `languages.CSharp.language_servers`, `lsp.<server>.binary.path` for pinned servers, `telemetry`.
- `config.jsonc_merge_deep(ctx, path, patch) -> bool`: parses JSONC (string-aware comment and trailing-comma stripping). It deep-merges: dicts recurse, patch leaves win, user keys are never removed. No semantic change means no write, and the bytes stay identical. A needed change first backs up to `settings.json.devboost-bak`, then writes merged JSON with a warning if comments were lost. An unparseable file raises `NeedsUser` naming the exact keys and is never rewritten.
- The seeded `settings.json` carries **no comments**. Explanations live in `docs/zed.md`.
- `keymap.json` seed is `[]` and is never merged afterwards.
- C# uses `csharp-ls` (`["csharp-ls", "!roslyn", "!omnisharp", "..."]`). No C# Dev Kit or Roslyn by default.
- `EDITOR=fresh` always. `VISUAL="zed --wait"` only in a local GUI session (Linux: `DISPLAY`/`WAYLAND_DISPLAY` set and not SSH; macOS: not SSH) and only when `zed` is on PATH. git `core.editor` stays unset.
- No secrets or API keys in any seeded file (agents reuse their own CLI logins).
- Free-for-commercial-use tools only. Local-first: nothing is fetched at run time except the Zed installer and Zed's own extension/agent downloads.
- Merge gates (constitution): `uv run ruff check`, `uv run mypy`, `uv run pytest` must all be clean. Tests are hermetic: use `FakeExecutor`, a `tmp_path` HOME, and no real network or Zed.
- Commits: Conventional Commits, **no** `Co-Authored-By` / Claude attribution (constitution).
- All commands below run from `engine/` unless stated otherwise.

## Decisions (spec gaps ruled on; the user was unavailable)

| # | Topic | Decision | Why |
|---|---|---|---|
| D1 | Arch/Omarchy install | Use the official `install.sh` on **every** Linux family, Arch included. Do not use pacman `zed`. | Arch's package ships the CLI as `zeditor` (it clashes with ZFS `zed`), which would break `VISUAL="zed --wait"` and the verify. One path means one verify. |
| D2 | Version pin | Do not pin (`ZED_VERSION` exists but is left at latest). `self_updating` stays `False`. | Zed auto-updates itself (`auto_update: true`), so a pin would be overwritten on first launch. Principle III pins apply to the LSPs Zed runs, and those stay pinned. |
| D3 | Module shape | One `zed` module does install + seed + required keys. There is no separate `zed-config` module. | This matches `Fresh` (install + seed). Verify re-checks the required keys, so every run repairs them. |
| D4 | Seeding without chezmoi ordering | `zed` seeds from the bundled `create_*` files when they are absent. It does **not** `require` `Dotfiles`. | `requires` pulls in the whole shell stack (starship, atuin…) for `devboost install editors`. The file content is the same either way, and chezmoi `create_` never overwrites. |
| D5 | Macos seam | `Zed.families = ("fedora", "debian", "arch")`. `zed_install_argv` raises `UnsupportedOS` for macOS. | Z2 adds `"macos"` and the cask branch and nothing else. The existing `zsh-plugins` design uses the same `families` pattern. |
| D6 | LSP binary path | Point at the **mise shim** `~/.local/share/mise/shims/<cmd>`, with `arguments` from TSV column 4. Only write entries whose binary exists on disk. | The shim path survives pin bumps (mise resolves the global pin, which is the TSV). Pointing at an absent binary would break that language in Zed. |
| D7 | Which servers get a path | `data/zed/lsp-binaries.tsv`: `basedpyright`, `ruff`, `tailwindcss-language-server`, `intelephense`, `tofu-ls`, `yaml-language-server` (mise), plus `csharp-ls` (`~/.dotnet/tools`, installed by `dotnet-lsp`). | Only servers that have a Zed adapter id get a path. TS (vtsls, the spec's choice), ESLint, Markdown, bash and TOML stay Zed-managed: they have no Zed adapter or no dev-boost pin. |
| D8 | First-run ordering | After installing, every LSP module (`LspModule` subclasses + `DotnetLsp`) calls `_zed.refresh_after_lsp`. | `graph.toposort` gives no order between unrelated modules. Without the hook, pins installed *after* `zed` would only reach Zed on the second run. |
| D9 | Terraform extension | Use `opentofu` (not `terraform`). | dev-boost's pinned server is `tofu-ls`, which the `opentofu` extension (Apache-2.0) runs. The `terraform` extension runs `terraform-ls`. |
| D10 | Tailwind class helpers | Use `classFunctions: ["cn", "clsx", "cva", "cx", "tw"]` instead of hand-written `classRegex`. | The pinned server (0.14.29) supports it, including `tw` tagged templates, and it needs no regex to maintain. |
| D11 | Tailwind in Blade | Add `languages.Blade.language_servers: ["tailwindcss-language-server", "..."]` plus `includeLanguages {php: html, blade: html}`. | Zed's Tailwind server does not attach to Blade by default (per the Blade extension README). |
| D12 | Agent entries | `agent_servers`: `claude-acp`, `codex-acp`, `pi-acp`, each `{"type": "registry"}`. | These are the ACP-registry ids. Zed downloads the adapters and each one reuses its own CLI login. There are no keys in the file. |
| D13 | Merge semantics | Lists are leaves (the patch replaces them). A user cannot turn off a required extension; it is re-enabled. `docs/zed.md` documents this. | This keeps the spec's "patch leaves win" rule simple and predictable. |
| D14 | Unparseable file through the LSP hook | Log a warning only. The `zed` module itself reports `NeedsUser`, which shows as `blocked`. | An LSP module must not fail because of the user's editor file. |
| D15 | `env.sh` now | Create `dotfiles/dot_config/devboost/env.sh` (POSIX) holding only the editor block, sourced by `shell.bash`. macOS M2 extends the same file. | The spec names `env.sh`, but it lands with macOS M2 and Z1 must land independently. |
| D16 | Inherited `VISUAL` | In a non-GUI session, unset `VISUAL` only when it equals `zed --wait` (for example, leaked from a tmux server started in the GUI). | This never clobbers a user's own `VISUAL`. |
| D17 | `file_scan_exclusions` | Restate Zed's default list, then add the spec's entries. | The setting **replaces** Zed's default (`.git`, `.svn`, …) instead of extending it. |
| D18 | Terminal shell | `terminal.shell: "system"`. | That is the user's login shell (bash on Linux, zsh on macOS) with no per-OS value to maintain. |
| D19 | Laravel Pint | Z1 does not wire Pint into Zed. The docs say to run it through `ddev exec vendor/bin/pint`. | Pint has no stdin mode for Zed's external formatter, and the spec says "per-project dev-dependency, as today". |
| D20 | Licences | Intelephense free tier (free for commercial use, already used by fresh), `csharp-ls` (MIT), Zed (GPL/AGPL, free), extensions (Apache/MIT). No paid tiers anywhere. | This follows the user's free-for-commercial-use rule. |
| D21 | Housekeeping | `devboost.lock` is not regenerated (it is already stale and outside this scope). `CLAUDE.md`'s mission line is left for the owner. The README is updated. | Keeps the PR focused. |
| D22 | Writes | The JSONC write is atomic (`*.devboost-tmp` + `os.replace`). | Zed live-reloads `settings.json`, so it must never see a half-written file. |

### Task 1: `config.jsonc_merge_deep`, a JSONC-aware deep merge

**Files:**
- Modify: `engine/src/devboost/exec/primitives/config.py`
- Test: `engine/tests/primitives/test_jsonc.py` (create)

**Interfaces:**
- Consumes: `devboost.core.errors.NeedsUser(reason: str, how_to_fix: str)`; `devboost.core.log.warn(msg: str)`.
- Produces (all in `devboost.exec.primitives.config`):
  - `strip_jsonc(text: str) -> str`: removes `//` and `/* */` comments and trailing commas outside strings.
  - `deep_merge(base: Mapping[str, Any], patch: Mapping[str, Any]) -> dict[str, Any]`: dicts recurse and every other patch value wins. It never mutates its inputs.
  - `jsonc_satisfies(path: str, patch: Mapping[str, Any]) -> bool`: pure check. Returns True iff the file exists, parses, and `deep_merge(current, patch) == current`. Absent or unparseable means False.
  - `jsonc_merge_deep(ctx: Ctx, path: str, patch: Mapping[str, Any]) -> bool`: returns True iff it wrote. It raises `NeedsUser` on an unparseable file and leaves that file untouched.

```python
# --- JSONC (Zed-style JSON with comments / trailing commas) ---------------------------------


def _skip_string(text: str, i: int, out: list[str]) -> int:
    """Copy the JSON string starting at text[i] == '"' into *out*; return the index after it."""
    out.append(text[i])
    i += 1
    n = len(text)
    while i < n:
        c = text[i]
        out.append(c)
        if c == "\\" and i + 1 < n:
            out.append(text[i + 1])
            i += 2
            continue
        i += 1
        if c == '"':
            break
    return i


def _drop_trailing_commas(text: str) -> str:
    out: list[str] = []
    i, n = 0, len(text)
    while i < n:
        c = text[i]
        if c == '"':
            i = _skip_string(text, i, out)
            continue
        if c == ",":
            j = i + 1
            while j < n and text[j] in " \t\r\n":
                j += 1
            if j < n and text[j] in "}]":
                i += 1
                continue
        out.append(c)
        i += 1
    return "".join(out)


def strip_jsonc(text: str) -> str:
    """Remove ``//`` and ``/* */`` comments and trailing commas, never touching strings.

    An unterminated block comment swallows the rest of the text, so the JSON parse that
    follows fails loudly instead of guessing.
    """
    out: list[str] = []
    i, n = 0, len(text)
    while i < n:
        c = text[i]
        if c == '"':
            i = _skip_string(text, i, out)
        elif text.startswith("//", i):
            j = text.find("\n", i)
            i = n if j == -1 else j
        elif text.startswith("/*", i):
            j = text.find("*/", i + 2)
            i = n if j == -1 else j + 2
        else:
            out.append(c)
            i += 1
    return _drop_trailing_commas("".join(out))


def deep_merge(base: Mapping[str, Any], patch: Mapping[str, Any]) -> dict[str, Any]:
    """Recursive merge: dicts recurse, any other patch value (lists included) wins.

    Keys only in *base* are always kept — this is how a user's own settings survive.
    """
    out: dict[str, Any] = dict(base)
    for key, value in patch.items():
        current = out.get(key)
        if isinstance(value, Mapping):
            out[key] = deep_merge(current if isinstance(current, Mapping) else {}, value)
        else:
            out[key] = value
    return out


def _parse_object(text: str) -> dict[str, Any]:
    data = json.loads(strip_jsonc(text))
    if not isinstance(data, dict):
        raise ValueError("top level is not a JSON object")
    return data


def _leaf_paths(patch: Mapping[str, Any], prefix: str = "") -> list[str]:
    out: list[str] = []
    for key, value in patch.items():
        dotted = f"{prefix}.{key}" if prefix else key
        if isinstance(value, Mapping) and value:
            out.extend(_leaf_paths(value, dotted))
        else:
            out.append(dotted)
    return out


def jsonc_satisfies(path: str, patch: Mapping[str, Any]) -> bool:
    """Pure check: does the JSONC file at *path* already contain every leaf of *patch*?"""
    p = Path(path)
    if not p.exists():
        return False
    try:
        current = _parse_object(p.read_text(encoding="utf-8"))
    except ValueError:
        return False
    return deep_merge(current, patch) == current


def jsonc_merge_deep(ctx: Ctx, path: str, patch: Mapping[str, Any]) -> bool:
    """Guarantee *patch* inside a user-owned JSONC file (e.g. Zed's settings.json).

    No semantic change → no write (a commented file stays byte-identical). A needed change
    backs the original up to ``<file>.devboost-bak`` and writes plain JSON atomically;
    comments are lost only then, and that is logged. An unparseable file is never
    rewritten: the user gets ``NeedsUser`` with the exact keys to add.
    """
    p = Path(path)
    raw = p.read_text(encoding="utf-8") if p.exists() else None
    current: dict[str, Any] = {}
    if raw is not None and raw.strip():
        try:
            current = _parse_object(raw)
        except ValueError as exc:
            raise NeedsUser(
                f"{path} is not valid JSON/JSONC ({exc})",
                "fix it (or delete it — dev-boost re-seeds a missing file) and re-run; "
                f"dev-boost must set: {', '.join(_leaf_paths(patch))}",
            ) from exc
    merged = deep_merge(current, patch)
    if raw is not None and merged == current:
        return False
    if raw is not None:
        backup = p.with_name(p.name + ".devboost-bak")
        backup.write_text(raw, encoding="utf-8")
        if strip_jsonc(raw) != raw:
            log.warn(
                f"{path}: rewritten to add dev-boost keys — comments/trailing commas were not "
                f"preserved; the original is at {backup}"
            )
    p.parent.mkdir(parents=True, exist_ok=True)
    tmp = p.with_name(p.name + ".devboost-tmp")
    tmp.write_text(json.dumps(merged, indent=2) + "\n", encoding="utf-8")
    os.replace(tmp, p)
    return True
```

`ctx` is unused today. It is kept for signature parity with `json_merge` and for a future privileged write (the spec fixes the signature).

```python
@dataclass(frozen=True)
class ServerPin:
    """One row of a bundled data/fresh/*.tsv: the in-repo pin for a language server."""

    lang: str
    cmd: str
    spec: str
    args: tuple[str, ...] = ()


def read_pins(tsv_name: str) -> list[ServerPin]:
    """Every server row (with its optional space-separated args) from data/fresh/<tsv_name>."""
    pins: list[ServerPin] = []
    text = resource_path("data", "fresh", tsv_name).read_text(encoding="utf-8")
    for line in text.splitlines():
        if not line.strip() or line.startswith("#"):
            continue
        cols = line.split("\t")
        if len(cols) >= 3:
            args = tuple(cols[3].split()) if len(cols) >= 4 else ()
            pins.append(ServerPin(cols[0], cols[1], cols[2], args))
    return pins


def all_pins() -> list[ServerPin]:
    """Pins from every bundled data/fresh/*.tsv — the single source of truth for versions."""
    return [
        pin
        for tsv in sorted(resource_path("data", "fresh").glob("*.tsv"))
        for pin in read_pins(tsv.name)
    ]


def read_servers(tsv_name: str) -> list[tuple[str, str, str]]:
    """(lang, fresh-cmd, mise-spec) rows from a bundled data/fresh/<tsv_name>."""
    return [(p.lang, p.cmd, p.spec) for p in read_pins(tsv_name)]
```

```python
"""Zed editor configuration — OS-agnostic (Linux now; macOS Z2 reuses it unchanged).

dev-boost seeds ~/.config/zed/{settings,keymap}.json once (the same bundled files chezmoi
`create_`s) and afterwards guarantees only the spec's must-have keys, via a comment-tolerant
deep merge. Language servers are pointed at dev-boost's pinned binaries (data/fresh/*.tsv).
"""

from __future__ import annotations

import json
import os
from collections.abc import Sequence
from pathlib import Path
from typing import TYPE_CHECKING, Any

from devboost.core import log
from devboost.core.errors import NeedsUser
from devboost.exec.primitives import config
from devboost.exec.resources import resource_path
from devboost.model import Ctx

if TYPE_CHECKING:  # runtime import would cycle: _lsp calls refresh_after_lsp
    from devboost.modules._lsp import ServerPin

_SEED_DIR = ("dotfiles", "dot_config", "zed")

#: Keys re-asserted on every run (spec "Must-have keys"); everything else is the user's.
_MUST_HAVE: tuple[tuple[str, ...], ...] = (
    ("auto_install_extensions",),
    ("agent_servers",),
    ("languages", "CSharp", "language_servers"),
    ("telemetry",),
)


def _home() -> Path:
    return Path(os.environ["HOME"])


def settings_path() -> Path:
    return _home() / ".config" / "zed" / "settings.json"


def keymap_path() -> Path:
    return _home() / ".config" / "zed" / "keymap.json"


def _seed_text(name: str) -> str:
    return resource_path(*_SEED_DIR, f"create_{name}").read_text(encoding="utf-8")


def seed_files() -> None:
    """Write each seed only when its target is absent — after that the user owns it."""
    for name, target in (("settings.json", settings_path()), ("keymap.json", keymap_path())):
        if not target.exists():
            target.parent.mkdir(parents=True, exist_ok=True)
            target.write_text(_seed_text(name), encoding="utf-8")


def _pick(data: dict[str, Any], path: tuple[str, ...]) -> dict[str, Any]:
    """The value at *path* re-nested alone: ("a", "b") → {"a": {"b": data["a"]["b"]}}."""
    value: Any = data
    for key in path:
        value = value[key]
    nested: dict[str, Any] = {path[-1]: value}
    for key in reversed(path[:-1]):
        nested = {key: nested}
    return nested


def read_lsp_map() -> list[tuple[str, str, str]]:
    """(zed-lsp-id, command, resolver) rows from the bundled data/zed/lsp-binaries.tsv."""
    rows: list[tuple[str, str, str]] = []
    text = resource_path("data", "zed", "lsp-binaries.tsv").read_text(encoding="utf-8")
    for line in text.splitlines():
        if not line.strip() or line.startswith("#"):
            continue
        cols = line.split("\t")
        if len(cols) >= 3:
            rows.append((cols[0], cols[1], cols[2]))
    return rows


def lsp_binaries(pins: Sequence[ServerPin], home: Path) -> dict[str, Any]:
    """``lsp.<id>.binary`` entries for every mapped server whose binary exists on disk."""
    by_cmd = {p.cmd: p for p in pins}
    out: dict[str, Any] = {}
    for zed_id, cmd, resolver in read_lsp_map():
        if resolver == "mise":
            pin = by_cmd.get(cmd)
            if pin is None:
                raise ValueError(f"lsp-binaries.tsv: {cmd!r} has no pin in data/fresh/*.tsv")
            path = home / ".local" / "share" / "mise" / "shims" / cmd
            args = list(pin.args)
        elif resolver == "dotnet-tool":
            path = home / ".dotnet" / "tools" / cmd
            args = []
        else:
            raise ValueError(f"lsp-binaries.tsv: unknown resolver {resolver!r} for {cmd!r}")
        if path.exists():
            out[zed_id] = {"binary": {"path": str(path), "arguments": args}}
    return out


def must_have_patch(pins: Sequence[ServerPin], home: Path) -> dict[str, Any]:
    """The keys dev-boost guarantees: sliced from the seed (one source) + pinned LSP paths."""
    seed = json.loads(_seed_text("settings.json"))
    patch: dict[str, Any] = {}
    for path in _MUST_HAVE:
        patch = config.deep_merge(patch, _pick(seed, path))
    binaries = lsp_binaries(pins, home)
    if binaries:
        patch["lsp"] = binaries
    return patch


def config_ok(pins: Sequence[ServerPin]) -> bool:
    return config.jsonc_satisfies(str(settings_path()), must_have_patch(pins, _home()))


def ensure_config(ctx: Ctx, pins: Sequence[ServerPin]) -> bool:
    """Seed if absent, then merge the must-have keys. True iff settings.json was rewritten."""
    seed_files()
    return config.jsonc_merge_deep(ctx, str(settings_path()), must_have_patch(pins, _home()))


def refresh_after_lsp(ctx: Ctx, pins: Sequence[ServerPin]) -> None:
    """Called by LSP modules after installing servers, so Zed sees them on the FIRST run
    (the plan has no ordering between `zed` and the *-lsp modules). A no-op when Zed's
    settings don't exist; an unparseable file is the `zed` module's to report, not ours."""
    if not settings_path().exists():
        return
    try:
        ensure_config(ctx, pins)
    except NeedsUser as exc:
        log.warn(f"zed: {exc}")
```

```markdown
# Zed — the default editor

`devboost install editors` (part of `full` and `omarchy`) installs [Zed](https://zed.dev) on
Fedora, Ubuntu and Arch/Omarchy with the official user-local installer
(`~/.local/zed.app`, `~/.local/bin/zed`; no sudo). Zed updates itself. GUI only — skipped on
headless servers. VS Code is opt-in: `devboost install optional-editors`.

## Seeded vs guaranteed

| | What | When |
|---|---|---|
| **Seeded** | `~/.config/zed/settings.json` + `keymap.json` (`[]`) | only if absent — then the files are **yours** |
| **Guaranteed** | `auto_install_extensions` (dev-boost's ids; yours are kept), `agent_servers` (Claude, Codex, Pi), `languages.CSharp.language_servers`, `lsp.<server>.binary` for dev-boost-pinned servers, `telemetry` (off) | every `devboost install` |

Guaranteed keys are **deep-merged**: your other keys (and your own keys inside those objects)
are never removed. If nothing needs changing the file is not touched (comments survive). If
something does, the original is saved as `settings.json.devboost-bak` and the file is rewritten
as plain JSON (comments are lost only then — a warning says so). If the file doesn't parse,
dev-boost changes nothing and reports `blocked` with the exact keys to add. Setting a
guaranteed extension to `false` does not stick — remove the extension from Zed instead of
fighting the merge, or drop the `editors` profile.

## What the seed configures

- **VS Code feel:** VS Code keymap, project panel left, minimap auto, breadcrumbs, autosave on
  focus change, format on save. Import your VS Code settings with the command palette:
  `zed: import vs code settings`.
- **Look:** Tokyo Night (follows the system light/dark mode), JetBrainsMono Nerd Font in the
  buffer and terminal, indent guides, rainbow brackets.
- **Intelligence:** inlay hints, inline git blame, diagnostics + git diff in the scrollbar.
- **Hygiene:** telemetry off; heavy/generated dirs hidden from the file tree and search
  (`node_modules`, `vendor`, `bin`, `obj`, `.venv`, `.ddev`, `.next`, `dist`, `.expo`,
  `ios/Pods`, `android/build`, `public/build`, `bootstrap/ssr`). Delete an entry from
  `file_scan_exclusions` if you need to browse it (e.g. a repo's `bin/` scripts).
- **Terminal:** your login shell.

## Per stack

| Stack | How |
|---|---|
| React / Next.js / React Native | TS/TSX via vtsls (Zed-managed); ESLint `source.fixAll.eslint` on format; Prettier on save |
| Tailwind (v3/v4) | built-in server (dev-boost-pinned); classes inside `cn()`, `clsx()`, `cva()`, `cx()`, `` tw`…` ``; also in PHP and Blade |
| Laravel / Inertia | `php` + `blade` extensions; Intelephense (free tier); Tailwind in `.blade.php` and `.tsx`. Pint is not wired into Zed — run `ddev exec vendor/bin/pint` |
| .NET | `csharp` extension with `csharp-ls` (no Roslyn/OmniSharp) |
| Python | basedpyright + ruff (formats on save) |
| DevOps | `opentofu` (tofu-ls), `dockerfile`, `docker-compose`; YAML/TOML built in |
| Misc | `toml`, `sql`, `env`, `make`, `git-firefly`, `tokyo-night` |

## Pinned language servers

Zed runs dev-boost's pinned servers — the same ones fresh uses — via their mise shims
(`~/.local/share/mise/shims/<cmd>`), and `csharp-ls` from `~/.dotnet/tools`. The map is
`data/zed/lsp-binaries.tsv`; the **versions** live only in `data/fresh/*.tsv`. To bump one, edit
its row there and re-run `devboost install <stack>` — the shim path doesn't change, so Zed
picks the new version up after a restart. Servers without a dev-boost pin (vtsls, ESLint,
Markdown, bash) are downloaded by Zed.

## In-editor agents

Claude (`claude-acp`), Codex (`codex-acp`) and Pi (`pi-acp`) are registered as ACP registry
agents: Zed downloads each adapter on first use; each reuses its own CLI login (see
[agents](agents.md)). No keys are stored in `settings.json`.

## `$VISUAL` / `$EDITOR`

`EDITOR=fresh` everywhere. `VISUAL="zed --wait"` only in a local desktop session (not over SSH)
and only when `zed` is installed — set in `~/.config/devboost/env.sh`. git has no
`core.editor`, so commit messages open in Zed on the desktop and in fresh over SSH.
```
